# Adv360 Pro — local keymap workflow

Local-only. No GitHub Actions, no web editor, no `make`. Edit a file, run a
script, flash two files.

## The one file you edit

`config/adv360.keymap` — all layers for both halves live here.
(`adv360_left.keymap` / `adv360_right.keymap` just `#include` it.)

Layer indices, in the order they appear in the file:

| # | Name | Reached by |
|---|------|-----------|
| 0 | Base | default |
| 1 | Kp (keypad) | `&tog 1` — the **keypad** key, toggles |
| 2 | Fn | `&mo 2` — hold either bottom-row **Fn** key |
| 3 | Mod | `&mo 3` — hold the **mod** key (top right) |
| 4–7 | Red / Purple / Cyan / Yellow | `status = "reserved"` — unused, free to claim |

Each layer is one `bindings = < ... >` block whose entries are laid out
positionally to match the physical keyboard. Key order is documented in
`assets/key-positions.md` + `assets/key-positions.png` — **read that before
moving anything**, because a binding list of the wrong length fails the build
with a devicetree error that doesn't name the layer.

`&trans` = fall through to the layer below. `&none` = dead key.

## Building

```bash
cd ~/projects/adv360
./build.sh          # both halves
./build.sh left     # left only — faster, use when only the left changed
```

Output lands in `firmware/` as
`<timestamp>-<commit>-left-clique.uf2` and `...-right-clique.uf2`.
First run pulls the ZMK toolchain image (slow); after that it's cached.

Both halves are built with `CONFIG_ZMK_STUDIO=y` on the left — the "clique"
variant — so this keymap and Kinesis's runtime Clique/Studio editor coexist.
`&studio_unlock` sits on the Mod layer (left **Esc** position) and is what lets
Studio connect.

## Flashing

Each half separately:

1. Hold **mod** + **macro1** → the *left* half mounts as a USB drive.
2. Copy the `-left-clique.uf2` onto it. It reboots itself.
3. Hold **mod** + **macro3** → the *right* half mounts.
4. Copy the `-right-clique.uf2` onto it.

There are also physical reset buttons on both halves (User Manual §2.7) if the
keymap is too broken to reach the Mod layer.

## When an edit doesn't seem to apply

A layout saved from **Clique / ZMK Studio shadows the flashed keymap.** Flash
`settings-reset.uf2` (in the repo root) to the affected half first, then flash
the real firmware. This is the most likely confusing failure — reach for it
before debugging your devicetree.

## Things already set up for you

- **`hm` hold-tap** (`config/adv360.keymap`, top of the file): 200 ms tapping
  term, 175 ms quick-tap, `tap-preferred`. Home-row mods need no new behavior,
  just bindings like `&hm LGUI A` / `&hm LALT S`.
- **`config/version.dtsi`** is generated by `build.sh` on every build and
  reverted afterward — never edit it, never commit it. `&macro_ver` (Mod layer)
  types the build stamp.
- **`config/macros.dtsi`** holds the macro definitions.

## Keeping it

```bash
git commit -am "keymap: swap caps for ctrl"     # commit every working keymap
git push                                         # fork is now just a backup
```

Pulling upstream fixes, if ever wanted:

```bash
git fetch upstream && git merge upstream/V3.0
```

Only `config/adv360.keymap`, `build.sh` and this file diverge from upstream, so
conflicts stay small.
